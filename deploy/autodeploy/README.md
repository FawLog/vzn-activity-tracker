# Event-driven production deployment (owner opt-in)

The default remains manual deployment. After explicit owner approval, install reviewed files once. No runner, SSH key, new public port, polling timer, or permanent sudo for an ordinary user. The webhook can only create a coalescing signal. A separate fixed root service independently queries GitHub, downloads exact artifacts and uses the existing deployment helpers. The root process downloads into its own private directory to avoid trusting files supplied by the listener. GitHub main is a production trust boundary: require reviewed PRs and all six checks, prevent force pushes and restrict direct writes. A compromised trusted build can still compromise application data. Automatic staging never replaces installed root helpers. Root control files and Compose must match the owner-approved hashes, so changes to these require manual review and reapproval, never automatic installation.

## Owner installation (only after successful CI and explicit privileged authorization)

1. Deploy this reviewed commit manually via the existing procedure first. Confirm health, verified backup, SHA and reserve. Inspect current root-owned helpers and compare hashes against the reviewed commit. No package installation or new firewall rules.
2. Create system user/group `vzn-webhook` with no login/home and no Docker/sudo membership; verify loopback TCP 8091 free. Create protected config under /etc/vzn-activity-tracker; store PAT in github-token (root:root 0600) and generate independent random webhook-secret (root:root 0600, at least 32 characters). Enter PAT privately on host, never as command argument or in chat/logs. Install optional minimum-reserve-bytes (root:root 0600) containing 536870912; default is the same. Larger values are supported.
3. From the reviewed source, install listener.py and worker.py as root:root 0755 under /usr/local/lib/vzn-autodeploy (directory 0755). Generate approved-controls.json using approve-controls.py with the reviewed source root and install root:root 0600 under /etc/vzn-activity-tracker. Verify all installed controls against it. Install the three systemd units in /etc/systemd/system as root:root 0644. Do not enable yet.
4. Back up the active VZN-only Nginx config and add nginx-location.conf inside its existing HTTPS server. Check nginx -t and reload gracefully; restore on failure. No other vhost or service changes. Confirm systemd supports LoadCredential and verify unit syntax.
5. Create root-owned autodeploy-paused marker in config. Enable/start vzn-webhook.service and vzn-autodeploy.path. Configure GitHub repository webhook: HTTPS URL https://vzn.fawlog.cc/webhooks/deploy, application/json, SSL verification enabled, Workflow runs events only, secret from host. Signed GitHub ping is acknowledged without triggering deployment; real signed successful push events accepted. Verify malformed requests rejected, listener cannot access PAT/Docker, signal can only activate fixed worker, pause prevents changes. Check existing service baseline and revoke temporary privileges.
6. Once approved, remove pause marker. Manually start vzn-autodeploy.service to reconcile current main once; subsequent successful main push CI events trigger immediately. If a notification arrives while updating, PathExists triggers another check after service exit. If VPS was offline, redeliver webhook or manually start worker; no periodic polling. GitHub does not guarantee automatic redelivery. Check journalctl -u vzn-autodeploy.service and current SHA. Never expose secrets.

## Operations

Pause: owner creates /etc/vzn-activity-tracker/autodeploy-paused; this prevents new updates, not interrupts in-flight deployment. Resume: remove marker and manually start worker. Failed or attempted SHA stays in /var/lib/vzn-autodeploy/attempted-sha until a different SHA succeeds or owner explicitly reviews and clears it. Interrupted updater marker requires existing manual recovery procedure. Do not clear it blindly. Disable watcher before manual deployment and ensure no worker active; re-enable after review. No automatic pruning of old staging, images or backups; disk blockers are intentional. Rotate PAT before expiry and update protected file; no restart needed for worker. Rotate webhook secret on both sides, restart listener. Logs use systemd journal; no external notifications in initial version.

The minimum 512 MiB reserve is additional to estimated unpack, staging and backup needs, not permission to fill disk. Root worker checks downloads and stage headroom; existing updater performs conservative peak check. Separate filesystem layouts and staging accumulation require owner preflight. Existing rollback remains authoritative. Manual installation and real GitHub delivery must be verified on host; CI unit tests only test selected gates.
