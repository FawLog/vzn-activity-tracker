# Calendar v3.8 — explicit session grouping

Calendar occurrences may store a reviewed common UTC cycle date and session key before any actual event exists. Bear groups across active alliance hosts; trap keys are unique across the group cycle. Foundry/Canyon group within one alliance and type; legion keys are unique. Explicit data entry resolves the common parent and actual host/time, atomically creates only the selected session if needed, and preserves existing evidence. Grouping does not guess membership by proximity or copy to future recurrences. Seven-day date guard is an application policy, not game mechanics. Linked entries cannot be regrouped; clear unlinked grouping before changing schedule identity/time or bulk shifting. Existing records are not automatically backfilled. Migration 0018 adds nullable columns and partial unique indexes. No OCR/analytics/CI changes.
