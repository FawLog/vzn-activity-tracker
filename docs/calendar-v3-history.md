# Calendar v3.9 — Event history and navigation

Calendar is now the primary navigation item after Overview. Existing /events and /events/:id URLs remain stable, with the Events page presented as Event history. Historical imports remain in Administration and are described as a fallback for records without a suitable schedule. History provides client-side search, event type and draft/published filtering, sorting, and links to the existing editor. The existing list endpoint and its scope are unchanged; no per-row requests. Overview's new-data actions lead to Calendar; recent actual records lead to History, with missing participant counts shown as unknown. Calendar links to History and resets record filters after schedule saves. Group-scoped responses are keyed to prevent old history/detail reads appearing in another scope. The existing manual editor remains usable for historical corrections. No database, backend, OCR, analytics or CI changes. Browser smoke tests exercise filtering, navigation and historical import. Global dirty-navigation guard and full planned-cycle completion protection remain v3.10 work.
