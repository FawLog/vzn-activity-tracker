# Calendar v4.6: Bear scheduling usability
Add event now opens the compact Bear Trap form by default. Choose first UTC cycle date, repeat hours (48 default, 47.5–168 supported), alliance and UTC time for each trap; Next UTC day covers cross-midnight traps. The order assigns Trap 1, Trap 2 etc. First cycle date is the UTC day of the earliest trap. Duration defaults to 30 minutes. Review the first three cycles, then save all traps in one transaction. With auto-renewal enabled the initial 60-day window is populated immediately, then the existing hourly cursor extends it. If disabled, four cycles are created. No event or attendance records are created.
A single idempotent API request reuses existing recurrence and grouping checks; any conflict rolls back every trap. Existing schedules are never overwritten. Use Edit schedule for time corrections to existing series. The advanced single-trap form remains available for exceptions and existing workflows. This batch creation does not implement coordinated cadence edits of existing multi-trap cycles. No migration or CI/CD changes.
